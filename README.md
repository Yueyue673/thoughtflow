# 清单法

你可以用它把一个项目的原文、整理和行动清单放在一起。原文是可以自由编辑的笔记。整理和任务由同一个配置的模型，根据项目上下文生成，结果还可以继续改。每个新项目有自己独立的内容和上下文。

界面支持手机横向切换、笔记和文件夹、清单排序和完成状态、任务颗粒度，也可以自己填写「如果……那么……」启动条件。生成任务时会先给出一份草稿，你再决定要不要加入清单。

## 运行

需要 Node.js 18 或更新版本，以及可以使用 OpenAI API 的账号和密钥。模型请求可能会产生费用。费用取决于模型、输入和输出量，具体请看 [OpenAI API 定价](https://openai.com/api/pricing/)。

在项目目录里，先设置进程环境变量，再启动服务。请在自己的终端里输入密钥，不要把它提交到代码库，也不要发给别人。

PowerShell：

```powershell
$env:OPENAI_API_KEY = '在这里填写你的密钥'
# 可选：选择支持 Responses API 和 Structured Outputs 的模型
$env:OPENAI_MODEL = 'gpt-4o-mini'
node server/local.mjs
```

macOS / Linux：

```sh
export OPENAI_API_KEY='在这里填写你的密钥'
# 可选：选择支持 Responses API 和 Structured Outputs 的模型
export OPENAI_MODEL='gpt-4o-mini'
node server/local.mjs
```

打开 `http://127.0.0.1:3000`。服务只监听本机。可以用 `PORT` 环境变量改端口。默认模型是 `gpt-4o-mini`。重新打开终端后，需要重新设置这些进程环境变量。`.env.example` 只列出可用变量，程序不会自动读取 `.env` 文件。

## 数据和上下文

项目、笔记、整理和清单保存在当前浏览器的 localStorage，不会自动跨设备同步。清除浏览器数据会删掉这些内容。可以在界面里用「备份」导出或恢复 JSON。恢复会替换这个浏览器里的全部项目，请先备份当前内容。每次请求整理、修改或生成任务时，当前项目的笔记、整理、意见、清单和颗粒度会先发给本机服务，再发到 OpenAI Responses API。服务端不会另外保存或记录项目内容，请求使用 `store: false`。不想把内容发给模型服务的项目，就不要使用其中的 AI 功能。

每个项目分别构建请求上下文。每次请求使用配置的那一个模型。同一页面里的生成请求会按顺序处理。不同浏览器标签页或设备之间没有全局请求锁。当前版本没有跨设备同步、多人协作，也没有服务端持久记忆。生成结果可能有误，请在加入清单或替换整理前检查。

## 开发与检查

项目使用原生 JavaScript 和 Node 内置 API，不需要安装第三方依赖。服务端入口是 `server/local.mjs`，页面资源在 `dist/`。测试使用模拟的模型响应，不会调用真实 API。运行测试：

```sh
node --test
```

本机服务供个人开发和使用，没有用户认证，请不要直接开放到公网。
