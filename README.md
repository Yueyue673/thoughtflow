# 清单法

把一个项目的原文、整理和行动清单放在一起。原文是可自由编辑的笔记；整理和任务由同一个配置的模型根据项目上下文生成，结果可以继续修改。新项目使用独立的内容与上下文。

界面支持手机横向切换、笔记与文件夹、清单排序和完成状态、任务颗粒度，以及自填的「如果……那么……」启动条件。任务生成会先给出草稿，由用户决定是否加入清单。

## 运行

需要 Node.js 18 或更新版本，以及可使用 OpenAI API 的账号和密钥。模型请求可能产生费用；费用取决于模型、输入和输出量，具体请查看 [OpenAI API 定价](https://openai.com/api/pricing/)。

在项目目录中，先设置进程环境变量，再启动服务。请在自己的终端输入密钥，不要将它提交到代码库或发送给他人。

PowerShell：

```powershell
$env:OPENAI_API_KEY = '在这里填写你的密钥'
# 可选：选择支持 Responses API 和 Structured Outputs 的模型
$env:OPENAI_MODEL = 'gpt-4o-mini'
node server/local.mjs
```

macOS / Linux：

```sh
export OPENAI_API_KEY='在这里填写你的密钥'
# 可选：选择支持 Responses API 和 Structured Outputs 的模型
export OPENAI_MODEL='gpt-4o-mini'
node server/local.mjs
```

打开 `http://127.0.0.1:3000`。服务只监听本机；可通过 `PORT` 环境变量修改端口。默认模型为 `gpt-4o-mini`。重新打开终端后需要重新设置进程环境变量。`.env.example` 仅列出可用变量；程序不会自动读取 `.env` 文件。

## 数据和上下文

项目、笔记、整理和清单保存在当前浏览器的 localStorage，不会自动跨设备同步；清除浏览器数据会删除这些内容。可以通过界面中的「备份」导出或恢复 JSON；恢复会替换该浏览器中的全部项目，请先备份当前内容。每次请求整理、修改或生成任务时，当前项目的笔记、整理、意见、清单和颗粒度会发送给本机服务，再发送到 OpenAI Responses API。服务端不另行保存或记录项目内容，请求使用 `store: false`。不要在不愿发送给模型服务的项目中使用 AI 功能。

每个项目分别构建请求上下文；每次请求使用配置的单个模型；同一页面会串行处理生成请求。不同浏览器标签页或设备之间没有全局请求锁。当前版本没有跨设备同步、多人协作或服务端持久记忆。生成结果可能有误，请在加入清单或替换整理前检查。

## 开发与检查

项目使用原生 JavaScript 和 Node 内置 API，不需要安装第三方依赖。服务端入口为 `server/local.mjs`，页面资源位于 `dist/`。测试使用模拟的模型响应，不会调用真实 API。运行测试：

```sh
node --test
```

本机服务供个人开发和使用，不提供用户认证；请勿直接开放到公网。
